# YouTube Learning Assistant — RAG Based Project

A Streamlit-based YouTube learning assistant that lets users ask questions about YouTube videos and receive answers grounded in the video's transcript.

## Features

- YouTube video discovery and selection
- YouTube transcript extraction
- Line-based chunking (~600 characters)
- ~120-character overlap between chunks
- Timestamp metadata for every chunk
- BAAI/bge-m3 semantic embeddings
- Persistent ChromaDB vector storage
- Cosine-distance retrieval
- Video-specific retrieval using `video_id`
- Distance-based relevance filtering
- Llama 3.2 answer generation through Ollama
- Clickable YouTube timestamps for retrieved sections
- Direct link to open the complete YouTube video
- Whole-video summary generation
- Quiz generation from the video content
- Streamlit user interface

## How It Works

### 1. Transcript extraction

The selected video's transcript is fetched with:

```python
api = YouTubeTranscriptApi()
transcript = api.fetch(
    video["video_id"],
    languages=["hi", "en", "te"]
)
```

Transcript entries contain text, start time, and duration.

### 2. Chunking

The transcript is divided into approximately 600-character chunks.

The current strategy also keeps approximately 120 characters of overlap between adjacent chunks. Whole transcript lines are retained, so the actual overlap can be slightly larger than 120 characters.

Each chunk stores:

```python
{
    "text": chunk_text,
    "start": ...,
    "end": ...
}
```

The timestamp is calculated from the first and last transcript lines:

```python
"start": current_lines[0].start,
"end": current_lines[-1].start + current_lines[-1].duration
```

### 3. Embeddings

Each chunk is converted into a semantic vector using BGE-M3:

```python
embeddings = model_l.encode(
    [chunk["text"] for chunk in chunks],
    normalize_embeddings=True
)
```

The model is cached with Streamlit's `st.cache_resource` so the model is loaded once and reused.

### 4. ChromaDB

The application uses persistent ChromaDB:

```python
client = chromadb.PersistentClient(path="./chroma_db")

collection = client.get_or_create_collection(
    name="YOU-TUBE",
    metadata={"hnsw:space": "cosine"}
)
```

Each chunk is stored with its embedding and metadata:

```python
{
    "video_id": video["video_id"],
    "start": chunk["start"],
    "end": chunk["end"]
}
```

The `video_id` allows retrieval to be restricted to the currently selected video.

### 5. Question retrieval

The user's question is embedded using the same BGE-M3 model:

```python
question_embedding = model_l.encode(
    question,
    normalize_embeddings=True
)
```

ChromaDB retrieves the closest chunks:

```python
result = collection.query(
    query_embeddings=[question_embedding.tolist()],
    n_results=5,
    where={"video_id": video["video_id"]}
)
```

The returned result contains documents, distances, and metadata.

Because the collection uses cosine distance:

**Lower distance means greater similarity.**

The current application filters retrieved chunks using a distance threshold.

### 6. Context and answer generation

Relevant chunks are combined into a context:

```python
context = "\n\n".join(relevant_chunks)
```

The context is passed to Llama 3.2 through Ollama with a prompt instructing the model to answer from the retrieved context.

### 7. Clickable timestamps

Every retrieved chunk contains:

```text
video_id
start
end
```

The start time is used to construct a YouTube URL. The UI can therefore show a section such as:

```text
▶ 3:58 - 4:50
```

Clicking the timestamp opens the selected video around that point.

## Current Limitations

- Retrieval quality depends on transcript quality.
- Chunk size is currently character-based and line-aware rather than fully semantic.
- The overlap is approximate because complete transcript lines are preserved.
- The distance threshold needs tuning using real questions.
- If the retrieved context is incomplete or ambiguous, the generated answer may still be incorrect.

## Learning Features

### Ask About This Video

Users can ask questions about the selected video. The RAG pipeline retrieves relevant transcript chunks and uses them as context for Llama 3.2 to generate a grounded answer.

The application also shows a **Relevant Sections** area containing clickable timestamp ranges. Clicking a timestamp opens the YouTube video at the corresponding point.

Example:

```text
📌 Relevant sections

▶ 3:58 - 4:50
[Relevant transcript chunk]

▶ 4:41 - 5:38
[Relevant transcript chunk]
```

### Whole Video Link

The application provides a separate button above the summary feature that opens the **complete YouTube video** directly.

This gives the user two ways to access the source:

1. Jump directly to a relevant section found by RAG.
2. Open and watch the complete YouTube video.

### Video Summary

The application can generate a summary of the **whole video**, helping users quickly understand the main ideas without watching the entire video first.

### Quiz Generation

The application can generate a quiz from the video's content to help users test their understanding and learn actively.

## Project Goal

The goal is to build a practical **YouTube Learning Assistant** that can:

1. Understand a selected video's transcript.
2. Answer questions using relevant transcript context.
3. Retrieve and display relevant sections of the video.
4. Provide clickable timestamps to the relevant sections.
5. Provide a direct link to the complete YouTube video.
6. Generate a summary of the whole video.
7. Generate a quiz for learning and revision.

This project demonstrates a practical RAG workflow using transcript processing, overlapping chunks, embeddings, vector search, metadata, retrieval, local LLM generation, source timestamps, summarization, and quiz-based learning.
